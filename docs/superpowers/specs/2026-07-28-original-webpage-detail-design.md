# 条目详情内嵌原始网页设计

## 目标

在首页和收藏页的条目详情操作区，为「手动 AI」左侧增加「查看原始网页」按钮。用户点击后，条目详情正文位置显示该条目的原文网页，而不是跳转离开当前阅读界面。

## 范围与交互

- 默认状态继续显示 RSS 正文或译文，现有标题链接仍可在新标签页打开原文。
- 「查看原始网页」按钮仅在已加载条目详情时显示，位置固定在「手动 AI」左侧。
- 点击按钮后，正文区域切换为以 `article.link` 为地址的 iframe；按钮文案切换为「返回正文」。
- 再次点击「返回正文」后，恢复原有正文/译文展示和当前语言选择。
- 切换至另一篇条目、关闭详情面板，或详情重新加载时，原始网页视图重置为正文视图。
- 首页与收藏页使用相同的组件和交互。

## 展示与异常回退

- iframe 占满详情内容可用宽度，并提供适合阅读区的最小高度、边框和圆角。
- 为 iframe 配置惰性加载与明确标题，减少首次渲染开销并提升无障碍语义。
- 很多第三方站点会通过 `X-Frame-Options` 或 CSP 拒绝 iframe 嵌入；浏览器通常无法可靠地向页面报告该情况。因此 iframe 区域始终提供「在新标签页打开原文」链接，作为可用的回退入口。
- 本功能不新增服务端抓取、缓存或反向代理，不改变文章数据结构与 API，避免代替用户访问任意外部站点所带来的 SSRF、安全清洗和内容缓存复杂度。

## 组件边界与数据流

- 新建轻量的原始网页内容组件，只接收原文 URL 并负责渲染 iframe 和回退链接。
- 首页、收藏页各自维护「是否查看原始网页」的 UI 状态，并将状态传给详情正文位置；不写入文章缓存、URL 参数或后端。
- 文章详情既有的正文、译文、媒体增强及手动 AI 逻辑保持不变。

## 测试

- 组件测试：iframe 使用给定 URL、具有加载与无障碍属性，并包含新标签页回退链接。
- 页面测试：首页与收藏页中，操作按钮位于手动 AI 之前；点击后切换至原始网页，再次点击恢复正文。
- 覆盖切换条目后原始网页视图重置的行为，防止一个条目的视图状态泄漏到另一条。
